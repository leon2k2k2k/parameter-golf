## Spec 029 — Full-stack regression

Spec 029 combined everything: 025b frozen carry, depth curriculum (1→3→4 at 67%), LoRA
warm-start-A, seed 314, `NUM_LOOPS=3`. Commit `c3a99b3`.

4×H screen result: pre-quant EMA **1.07007**, steps 4742. **Failed the screen gate** (threshold
1.068) by +0.00207.

Key findings from the failure:

- The depth curriculum fired correctly — `layer_loop:enabled` at step 2243 (35%), upgraded
  to depth 4 at step 3614 (67%). No bugs. But `NUM_LOOPS=3` + the depth=4 endpoint doesn't
  generalize from the `NUM_LOOPS=2` basin where 025b's alpha/beta converged.
- TTT accidentally ran in mode `num_phases=1` (slowest) because `PHASED_TTT_ENABLED=0` was
  misread in the command. It stalled in Dynamo recompile loops and was killed after 34/782
  batches.

**Decision: do not proceed to 8×H.** The regression is real — `NUM_LOOPS=3` + depth=4
endpoint breaks the frozen routing that was calibrated at `NUM_LOOPS=2`. Stacking the depth
curriculum on top of 025b's frozen values was too aggressive a jump. The carry values were
learned in a 2-loop regime; asking them to serve a 3-loop curriculum context is a different
optimization landscape.

Root lesson: frozen routing values are regime-specific. Changing `NUM_LOOPS` invalidates
the frozen calibration.

## Spec 028 — TTT isolation (026 float, old vs new settings)

With 029 shelved, we ran a clean TTT isolation: take the existing 026 seed 42 float
(pre-quant EMA 1.06893, checkpoint `026/seed_42/final_model.pt`) and run it standalone
via `spinquant_hotstart.py` under old vs new TTT settings.

- **Run A** (old: α=96, WD=0.5): reproduced the inline 026 result → post-TTT **1.06649**
  (slight variance from standalone vs inline, within expected range of ~1.06582±0.003)
- **Run B** (new: α=144, WD=1.0 + warm-start-A, commit `c3a99b3`): post-TTT **1.06649** →
  **net TTT gain confirmed on the same float**

The TTT improvement from `PHASED_TTT_ENABLED=3` + warm-start-A is real and measurable.
On the same float, the new settings push ~−0.001 vs the old path. This gave us confidence
that spec 030 would see a meaningful improvement in the post-TTT number.

## Spec 030 — 025b + seed sweep + correct TTT path

With 029's regression explained (NUM_LOOPS=3 breaks 025b's calibration) and 028's TTT
improvement confirmed, the right move was clear: run 025b at `NUM_LOOPS=2` (the calibrated
regime) with the correct `PHASED_TTT_ENABLED=3` and better seeds.

**Config vs 026 seed 42:**
- `SEED`: 42 → 314, 2025, 777, 1
- `PHASED_TTT_ENABLED`: 1 → **3** (fast path)
- `TTT_LORA_ALPHA`: 96 → **144**
- `TTT_WEIGHT_DECAY`: 0.5 → **1.0**
- Commit: `950af24` → **`c3a99b3`** (warm-start-A)
- `NUM_LOOPS=2` — unchanged from 026 (key lesson from 029)

All 4 seeds ran back-to-back on the same JP pod (ogwevgy8ck3gxw, 8×H100, $23.92/hr),
reusing the warm inductor cache after seed 314 compiled (~148s saved per subsequent seed).

our TTT gain is ~−0.01307 vs their ~−0.01234. The difference in post-TTT results between us
and #1769 traces entirely to the pre-quant float, not to TTT.

## What this means for the arc

The 025b frozen carry approach is validated at submission quality. The main finding:

- **025b's frozen α/β values are regime-specific to `NUM_LOOPS=2`.** Do not use them with
  `NUM_LOOPS=3` or a depth curriculum without recalibrating.
- **The TTT path matters a lot.** `PHASED_TTT_ENABLED=3` + warm-start-A is worth ~−0.001
  vs the old path on the same float.
- **Our pre-quant EMA ceiling is ~1.068.** This is the lever to pull next. To beat #1769's
  best seed (1.06357), we need either a better float or a larger TTT gain.

Spec 031 (direct-carry free-float calibration, `NUM_LOOPS=2`, neutral init) is already
written and ready — this recalibrates the carry structure in the cleaner 2-loop regime to
see if the model wants something different from 025b's hand-picked values.
