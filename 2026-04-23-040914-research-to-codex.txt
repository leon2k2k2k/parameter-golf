❯ okay what is this free-floating thingy?                                       

● Here's the idea in plain terms:

  What the frozen alpha is:
  The cross-layer carry weights (alpha/beta) in 025b are hardcoded constants —
  e.g., beta[L3] = 1.5973, alpha[L4,L4] = −0.348. Those specific numbers came
  from running 024b with learnable alpha, letting training discover them, then
  reading off the converged values and baking them in.

  The problem with 029:
  Those baked-in values were calibrated under NUM_LOOPS=2. In 029 we changed to
  NUM_LOOPS=3 + depth curriculum (depth grows 1→3→4). Different loop dynamics →
  different optimal alpha/beta. But we used the old NUM_LOOPS=2 values anyway,
  which is why it regressed.

  What "free-floating" means:
  Run a training with alpha/beta set as learnable parameters under the new
  regime (NUM_LOOPS=3 + depth curriculum). Don't submit it — just let it train
  to convergence, then read off what values alpha/beta settled at. Then freeze
  those new values into the code and run the real experiment.

  Why bother freezing at all?
  Learnable alpha adds a small number of parameters to the 16MB budget. Frozen
  constants are free — they cost zero bytes in the submission. So the freeze
  buys you a few extra model parameters "for free."

  So the workflow would be:
  1. Free-float run (cheap, just to discover the right constants)
  2. Bake values in
  3. Real run with NUM_LOOPS=3 + depth curriculum + correct frozen alpha

  Does that match what you were thinking?
