## Hypothesis

Per-pass activation-side rank-2 LoRA on MLP up/down projections, stacked on top of the 051 AC-fix levers. Each loop pass applies a learned delta `A@B` (pre-materialized outside compile via `@dynamo.disable`) to the MLP hidden activations, giving each pass a distinct functional role without duplicating weight storage. The 1797 baseline has a simpler compile graph than the 045 stack, reducing interaction risk.

## Code changes

Branch: `exp/050B-lora-on-1797` @ `b6305c8`
Train script: `records/track_10min_16mb/2026-04-27_050_PR1797_Base_BOS_Fix/train_gpt.py`

Key diffs vs 051 (050A):
- `Hyperparameters`: added `loop_ffn_lora_rank`
- `Block.forward`: optional `lora_delta_up`, `lora_delta_down` kwargs; applied as `h += F.linear(x, delta_up)` / `out += F.linear(h, delta_down)` in MLP path
- `GPT.__init__`: `loop_ffn_up/down_lora_A/B` params `[passes, loop_layers, rank, dim]`; kaiming-A / zero-B init; `_enc/_dec_ffn_lora_info` index tables
- `_compute_lora_deltas()`: `@torch._dynamo.disable` — materializes full `A@B` deltas in eager to avoid narrow-K (rank=2) Triton autotune hang
- `_forward_hidden`: calls `_compute_lora_deltas()` once before enc loop, slices per-step, passes to block calls
