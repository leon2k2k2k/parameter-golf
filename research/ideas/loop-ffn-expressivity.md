# Idea: More expressive FFN in the recurrence loop

**Created:** 2026-04-27  
**Status:** Exploration — multiple candidate techniques  
**Related specs:** 047C (per-pass LoRA, queued)

## The problem

Our loop band (layers 3–5, passes 0/1/2) uses **fully tied FFN weights**. ALBERT
(1909.11942 Table 4) measured that FFN tying is the dominant quality cost in
tied/depth-recurrent transformers — ~1.4–2.8 GLUE points — while attention tying
is approximately free.

In our setup we run 3 loop passes, so each FFN weight is used 3× per forward. The
FFN has no way to "know" which pass it's on and therefore cannot specialize: pass 0
should do something different from pass 2 (early feature extraction vs. refinement),
but the weight sees the same linear map either way.

This is the FFN version of the problem the α/β recurrent carry (spec 015) solved for
the attention layer.

## What the literature says

Fresh literature search (2026-04-27), ranked by parameter efficiency:

### Tier 1: Near-zero overhead (< 10K params)

**1. Pass-indexed scale vectors** — arxiv 2410.01405 (ICML 2025)  
A sinusoidal embedding of the loop index `t` feeds a tiny shared MLP → outputs a
scalar or vector γ(t) that gates the FFN output. No per-pass stored weights beyond
a shared MLP (d×256 + 256×d ≈ 256K, but this is shared across all passes, not
per-pass). The key insight: passes need different *phase signals* more than different
weights.  
**Result:** PPL 10.91 → 10.28 on their looped baseline (−0.63).

**2. AdaLN-style per-pass modulator** — arxiv 2602.11451 (LoopFormer)  
Same idea, richer: each pass gets (γ_msa, γ_mlp, α_msa, α_mlp) — four d-dim
vectors gating both the attention and FFN residual connections, plus RMSNorm scale
modulation. Generated by a shared MLP from a Fourier feature of the normalized pass
fraction (t/T). Zero-initialized → transparent at init.  
**Result:** Same dataset, PPL 10.91 → 10.28, zero-shot acc +1.93 pp.

**Commentary for our setup:** Both of these essentially solve the "which pass am I
on?" problem with a small conditioning signal. The parameters are shared (not
per-pass), so the overhead is essentially a constant ~50–200K regardless of how
many loops you run. At our model scale (~16M params), this is 0.3–1.2% overhead.
This is cheaper than per-pass LoRA and arguably more principled: the MLP's
expressivity at each pass is still its full rank, you're just steering its
output differently per pass via a learned time-code.

**This may be the most efficient lever we have not tried.**

### Tier 2: Low overhead (50–200K params)

**3. Per-pass LoRA on FFN** — arxiv 2410.20672 (Relaxed Recursive, ICLR 2025)  
Add per-pass rank-r LoRA to each FFN (up and down projections). At rank 4 on both
sites: 3 passes × 3 layers × 2 sites × (d×r + r×mlp_dim) ≈ 3×3×2×(512×4 +
4×2048) = 9×2×10240 ≈ 184K params.  
Already specced as 047C. The ALBERT-motivated approach.

**4. Mixture of LoRAs (MoL)** — arxiv 2512.12880  
Instead of one fixed LoRA per pass, maintain a pool of K LoRA experts and route
each token to top-K based on its content. The routing is *token-conditional* rather
than *pass-conditional* — complementary to per-pass conditioning. Key trick: at
inference, the expert mixture can be merged into a single effective LoRA → no
deployment overhead.  
**Result:** +1.16 GLUE pp over fixed LoRA on 75M ALBERT-like model.

**Commentary:** MoL and per-pass LoRA attack different axes of variation:
- Per-pass LoRA: same token, different pass → different correction  
- MoL: same pass, different token → different correction  
They could be stacked (pass-indexed routing of a token-conditional LoRA pool) but
that gets complex.

### Tier 3: Architectural (more invasive)

**5. SpiralFormer resolution routing** — arxiv 2602.11698  
Each pass uses a different "resolution" of the hidden sequence via learned
downsampling/upsampling linear layers. The FFN at pass 0 sees coarse global context
(chunked sequence), pass 1 sees finer structure, pass 2 sees full resolution. This
induces structural specialization per pass without changing the FFN weights.  
**Result:** PPL −0.09–0.10 at 410M–1B scale; FLOPs simultaneously drop 7–10%.  
**Overhead:** ~100–300K for the router linears.  
**Complexity:** Requires changing the forward pass to handle variable-length hidden
states between passes. More invasive than anything above.

**6. VersatileFFN (per-token pass count)** — arxiv 2512.14531  
Instead of differentiating FFN weights, adaptively assign pass counts per token: hard
tokens get more passes, easy tokens fewer. A tiny predictor head (~2K params) routes
each token. Orthogonal to weight differentiation — can be combined.  
**Result:** +3.73 pp accuracy (combined with their width-versatile path at 1.21B).

**7. Ouroboros (hypernetwork-conditioned LoRA)** — arxiv 2604.02051 (April 2026)  
A Controller hypernetwork reads the current hidden state and generates a diagonal
modulation for LoRA bases. Both input-conditioned and pass-conditioned. Very
expressive.  
**Caveat:** Does not yet generalize to held-out text (training distribution
overfit). Promising direction, not production-ready.

## Synthesis for our setup

Our constraints:
- 16MB compressed cap (42KB headroom currently)
- 3-pass loop band (layers 3–5)
- ~16M param model
- Each new param either trains at full size (compressed at 6-bit) or needs special treatment

**The hierarchy of ideas, simplest to most invasive:**

### Level 0: Pass-index conditioning (NEW — not specced yet)
Add a learned per-pass scale/shift to the FFN output of loop layers.
Two variants:
- **Simple:** `loop_pass_scale[p, i]` — learned vector (model_dim,) per (pass, layer).
  Init to 1. Multiplicative gate on FFN output. Params: 3×3×512 = 4,608. 
  Overhead: < 1KB compressed. Basically free.
- **Rich:** Small MLP from sinusoidal pass embedding → (γ, β) per loop layer.
  Params: ~50–100K shared. ~20KB compressed.
- **Even richer:** AdaLN-style: also modulate the RMSNorm scale before FFN.
  Same param count as Rich, more expressive.

This is motivated by the LoopFormer/2410.01405 finding that pass-phase signals give
+1.93pp zero-shot accuracy improvement at near-zero cost. We already have
`loop_iter_embeds` which adds a learned vector to x at the loop entry point — but
that only acts at the start, not inside each FFN within the pass.

### Level 1: Per-pass LoRA on FFN (spec 047C, rank 2–8)
Already queued. The direct ALBERT-motivated fix. Rank 2 = ~92K params, Rank 4 =
~184K, Rank 8 = ~368K. All small relative to the model.

### Level 2: Combined (pass conditioning + LoRA)
If Level 0 gives signal and Level 1 gives signal independently, combining them
may be the best path. The conditioning tells the FFN "which phase", and the LoRA
gives it actual weight expressivity in that phase.

### Level 3: MoL (token-adaptive LoRA pool)
If the bottleneck is token diversity rather than pass diversity (i.e., 047C helps
but not enough), try MoL on top. 4 experts rank-4 on the loop FFN = ~200K params
extra, merges to a single LoRA at inference.

### Level 4: SpiralFormer-style resolution scheduling
Most invasive. Only if Levels 0–3 are saturating. Would require significant forward
pass changes. Keep as a long-term idea.

## Recommended next spec after 047C

**047D — Per-pass FFN scale-shift (pass-index conditioning)**  
`LOOP_PASS_SCALE=1` — learned per-(pass, layer) scale vector on FFN output.  
Init to 1 (transparent). Params: 3×3×512 = 4,608. Zero additional compressed bytes
(too small to matter individually, compresses to ~100 bytes).

This is the fastest experiment to run and is motivated by LoopFormer showing +1.93pp
at similar near-zero cost. If it gives even −0.0005 bpb it's worth keeping.

Then compare 047C (LoRA) vs 047D (scale) and consider combining.

## Open questions

1. Does `loop_iter_embeds` (added at loop entry) partially subsume the pass
   conditioning signal? It adds a constant per-pass offset to x before layers
   3–5 run, but it doesn't modulate the FFN output directly. Likely complementary.

2. Would per-pass FFN scale interact badly with the α/β recurrent carry (spec 015)?
   The carry already modulates how much of the loop-layer output bleeds into the
   next pass. Adding a scale on the FFN output within the same pass adds another
   lever on the same pathway. Could be redundant or could give finer control.

3. At what rank does per-pass LoRA saturate? Relaxed Recursive uses rank up to 512
   on much larger models. For a 16M param model with 3-pass loops, rank 2–4 is
   probably the sweet spot. Rank 8 might already overfit.

4. Does quantizing the LoRA A/B matrices at int4 vs int6 hurt quality significantly?
   The A/B matrices are small and poorly represent with low-bit quant. Consider
   keeping them in int8 or FP16 and only quantizing the main FFN weights.
